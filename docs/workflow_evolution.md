## 目标与边界

- 为现有 `.codex/AGENTS.md` + `共享指南目录` 体系建立轻量、证据驱动的任务内改进与周期审视机制。
- 不承诺模型自我训练，不搭新框架、新目录或新调度系统；复用现有文件与现有 Codex 调度。
- 周期审视不修改具体项目代码或配置；仅引用本轮范围内、允许访问的任务证据。项目特有问题留在对应项目的授权任务内处理。

## 1. 事件驱动记录（任务内）

- 触发事件：重复失败、人工纠偏、上下文遗失、委派环境/额度失败、验证缺口、重复操作。
- 命中事件时先复用原任务已有的记录与产出，不另建平行台账。
- 仅把可定位的摘要（任务标识 + 文件/行或日志锚点）写入本机私有审视日志（格式见 [日志模板](../examples/workflow_evolution_log.md)），不复制原文。
- 建议每周一次，是否启用及具体时间由使用者决定；已存在调度则不重复创建。

## 2. 审视输入与覆盖

- 读取：上次 log 的审视时间、覆盖范围、未决项；全局入口指南与本轮已改动的指南；本任务证据，以及日志中显式登记且当前有权限访问的项目任务证据。
- 不扫描全部私人对话，不遍历代码库，不读取凭据。
- 看不到的证据直接在 log 中记为「覆盖不足」，不得宣称全部项目健康。
- 没有新证据、也没有失效链接等确定问题时结束，不为周期而制造修改。日志时间戳、审视游标和本机制的备份文件变化不算新的问题证据。

## 3. 审视清单

- 规则冲突、规则重复、规则失效（指向的文件/锚点/工具已不存在）。
- 上下文恢复是否存在重复劳动：同一信息被多次重建或重述。
- 执行者选择与委派是否按任务规模、风险和独立性执行。
- 验证是否真的证明了目标，还是只做了形式检查。
- 已有 Skill 的适用性，以及重复出现的 SOP 候选。
- Skill 只使用已暴露的元信息；未经用户请求，不读取、不调用 `SKILL.md`。
- 周期审视不自动联网追热点；只有出现具体技术疑问时才定向核验原始来源，并在结论中标注核验日期。

## 4. 改进闭环

- 流程：问题证据 → 根因 → 选最小修正 → 保存 before 与 diff → 验证 → 在 log 记录「观察 / 保留 / 修正 / 撤回」。
- 优先修真实的工具缺口与验证缺口，或删除重复规则，而不是添加口号式约束。
- 不把所有执行失败归因于模型能力；先查工具、上下文、规则与验证设计。
- 每轮最多处理 3 个有证据的小问题，其余原样保留。
- 进入新问题前，先复核上一轮标记为「待观察」的项。

## 5. 自动改动范围与提案范围

- 允许自动改动，且仅限：现有授权内、非语义的文档错字与格式、已确认目标的失效链接、不丢失任何约束的重复正文收敛。
- 自动改动的文件范围仅限使用者明确授权的全局入口与共享指南目录中的 Markdown 文档；日志按本指南更新。不得借此新增或放宽自身授权，不自动修改本机制的授权、限制或调度范围。
- 只出「具体可审查提案」的事项：实质性规则、模型路由与额度策略、权限/验收/Skill 启用机制、新 Skill、脚本安装与代码改动。若已有针对性授权，则按该授权的范围实施，不外扩。
- 修改前保存目标基线，写入前再次核对内容或 hash；期间发生变更就停止写入，重读合并或保留提案，不能覆盖用户或其他任务的新修改。
- 需要权限时使用宿主机制申请；被拒绝时停止该写入并记录具体缺口，继续不依赖该权限的工作，不绕过拒绝。

## 6. 验证与回滚

- 文档类改动：检查链接与锚点、检查 diff、确认每条被改约束的 owner 仍然明确。
- 获准的语义流程改动：优先复核所针对的历史失败，并检查代表性正常场景；无可重放记录时说明替代验证与限制，不假造回放结果，不降低现有强制验收标准。
- 仅通过静态文档检查不等于开发效率提升；缺少实战证据时记为「观察中」，下次出现相关证据再决定保留或撤回。
- 回滚只回滚本机制自身的改动，且先确认目标文件在此之后未被改写；若已被改写，只能提交提案，不得覆盖用户的新变更。

## 7. 日志内容

- 每条记录只含：日期、实际覆盖范围、问题来源、变更位置与 before 或 diff 的索引、验证证据、决定或待观察的下一步。
- 本轮无问题时，只更新上次审视时间与覆盖范围，不新增空日志条目。
- 不编造节约的 token 数、时间或任何百分比。

## 8. 委派与审查

- 按 [agent_selection.md](agent_selection.md) 的分工执行委派，Root 保留最终决定权。
- 以整项审视的实际工作量判断委派，不拆小操作规避规则；简单且低风险的工作可直接做，独立审查仍按 [engineering.md](engineering.md#independent-review-policy) 触发。

## 调度与运行前提

建议每周审视一次；首次启用调度需使用者明确授权。具体周期与启停由 Codex 自动化配置管理，修改文件不等于修改调度。运行结果以调度器实际记录为准，创建成功不代表未来每次执行都已验证。自动化不可用时可在现有任务中手动要求“按 workflow_evolution.md 审视”，不偷偷添加系统定时器或后台进程。
