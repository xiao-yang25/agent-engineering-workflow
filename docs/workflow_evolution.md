# 工作流改进

**简体中文** · [English](en/workflow_evolution.md) · [文档首页](../README.zh-CN.md#指南导航)

用重复问题证据做可验证、可撤回的改进。

## 目标与边界

- 复用现有入口、指南和 Codex 调度；不承诺自训练，不建新框架、目录或调度。
- 周期审视不改项目代码/配置，只用授权证据；项目问题留在原任务。

## 1. 事件驱动记录（任务内）

- 重复失败、纠偏、上下文遗失、委派/额度失败、验证缺口或重复操作触发记录。
- 复用原记录，不建平行台账。
- 私有本机日志只写任务标识及文件/行或日志锚点，不复制原文；见[模板](../examples/workflow_evolution_log.md)。
- 建议每周审视；启用和时间由用户决定，不重复调度。

## 2. 审视输入与覆盖

- 读取上次范围/未决项、本轮指南、本任务及日志登记的授权项目证据。
- 不扫私人对话、代码库或凭据；不可达证据记“覆盖不足”，不宣称全部健康。
- 无新证据或确定问题时结束，不制造改动；时间戳、游标、备份不算证据。

## 3. 审视清单

- 检查冲突/重复/失效规则、恢复重复劳动、委派适配、验证有效性及 Skill/SOP 候选。
- 只用 Skill 元信息；未经请求不读、不调用 SKILL.md。
- 不自动联网追趋势；具体疑问才核验原始来源并记日期。

## 4. 改进闭环

- 证据 → 根因 → 最小修正 → 保存 before/diff → 验证 → 记录“观察/保留/修正/撤回”。
- 先修工具/验证缺口或去重；先查工具、上下文、规则、验证，不把失败都归因模型。
- 每轮最多处理 3 个证据问题，其余不动；先复核上轮“待观察”项。

## 5. 自动改动范围与提案范围

- 只在既有授权内自动处理非语义 Markdown 错字/格式、目标已确认的失效链接、且不丢约束的重复正文。
- 文件仅限用户明确授权的全局入口和共享指南目录；不得借机制新增/放宽权限或改变其授权、限制、调度。
- 实质规则、模型/额度、权限、验收、Skill、新脚本/代码只给可审提案；已有授权时按范围实施。
- 修改前保存基线，写入前复核内容/hash；期间变化则重读合并或保留提案，不能覆盖用户或其他任务的新改动。
- 权限被拒则停止写入、记录缺口，不绕过拒绝。

## 6. 验证与回滚

- 文档检查链接、锚点、diff 和约束 owner。
- 授权的语义改动复核目标历史失败及代表性成功场景；无法重放时说明替代证据与限制，不伪造结果或降低门槛。
- 静态检查不能证明效率提升；无任务证据时标“观察中”，待后续证据决定。
- 只回滚本机制的改动，且先确认文件之后未变化；有新变化只能提案，不能覆盖。

### 小型真实任务回归集

可复用的成功产物与做法由原项目或原任务维护；此处的样例用于检验工作流改动，不因一次成功就认定流程改善，也不把项目资产复制到私有索引。

- 从当前任务或日志已登记、仍有授权的证据中选少量代表样例：目标历史失败及需保持的成功场景。先覆盖本次改动，不为凑数量扫描其他任务；索引复用私有日志和原任务记录，不把个人案例写进公开仓库。
- 每个样例关联原始证据及版本，明确输入/前提、预期结果、验收入口和适用边界。核对实际产物或最终状态，不能只以 Agent 自述完成作为通过依据。
- 改动前保存基线，改动后用相同样例和验收标准比较；记录指南/模型/环境版本及影响可比性的差异。尽量一次调整一个主要因素，不能把无法隔离的结果归因于某一改动。
- 对受随机性影响的关键样例，在既有授权和预算内预先确定重复次数，记录全部尝试而非只挑成功结果。重放沿用宿主权限与操作限制；无法安全重放或前后条件不可比时，说明替代证据和缺口，保留“观察中”。
- 样例与判据仅因需求、契约或新证据变化而修订，并保留理由与旧版本索引；不能为让分数变好而删除失败样例或放宽判据。按实际结果决定保留、修正或撤回；样例数量、静态通过或一次成功都不能单独证明整体改进。

## 7. 日志内容

- 每项只写日期、实际范围、问题来源、位置及 before/diff 索引、验证、决定或观察下一步。
- 无问题时只更新审视时间和范围，不加空条目。
- 不编造 token、时间或任何百分比节省。

## 8. 委派与审查

- 按 [agent_selection.md](agent_selection.md) 委派，Root 保留最终决定。
- 按整项审视工作量判断，不拆小规避；独立审查仍按 [engineering.md](engineering.md#independent-review-policy) 触发。

## 调度与运行前提

首次启用调度必须由用户明确授权；周期和启停以 Codex 自动化配置为准，编辑文件不改变调度。运行以调度器记录为准，创建成功不证明未来运行已验证。自动化不可用时可在当前任务手动要求审视；不得暗加系统定时器或后台进程。
