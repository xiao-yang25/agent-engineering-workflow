# 项目接入

**简体中文** · [English](en/project_workflow.md) · [文档首页](../README.zh-CN.md#指南导航)

保留项目约定，只补当前工作所需的入口和证据。

## 用途与触发

本指南用于建立、检查和维护项目专属规则，不保存具体业务事实或强制目录树。共享政策见 [engineering.md](engineering.md)，委派和证据交付见 [agent_selection.md](agent_selection.md)。

适用于首次接入且入口未知、用户要求建立/改造体系，或开发中发现影响当前任务的规则、上下文、运行或验收缺口。已接入项目复用现有知识；日常任务只补必要缺口，整体盘点需用户明确要求。

授权目标所需的规则建设可继续；纯咨询或只读审查只报告。本指南不扩大文件、网络、资料或预算权限，不要求重复确认，也不自动创建或启用 Skill。

## 共用准备与来源

先确定项目根、任务范围、用户已有修改和团队规则，再定位：

| 事实 | 优先入口 |
| --- | --- |
| 目标行为与约束 | 已接受需求、项目 AGENTS、README、契约、设计决定 |
| 当前结构与路径 | 相关代码、构建/部署配置、架构说明 |
| 正确性检查 | 测试说明、脚本、注册、CI、目标环境 |
| 未完成工作接续 | Issue、计划、调查记录、内部文档、证据索引 |

按[来源规则](engineering.md#intended-behavior-and-source-authority)区分契约、描述、观察和未知。代码、测试和历史报告不自动成为正确契约；性能、兼容、恢复和数据保留规则不得为填模板而编造。

不读无关目录、凭据或现场数据，不因设备列在文档中就连接。入口不可达时记录缺口和影响。

## 全新项目：随首个增量建立

1. 明确使用者、核心场景、目标/非目标、硬约束、首个结果和验收依据。
2. Root 决定技术和结构取舍；Worker 整理资料、验证可行性、执行方案，关键未决项保持显式。
3. 先打通一条可运行、可验证的完整路径及必要依赖、构建、运行和检查入口。
4. 随已确认事实建立最小项目 AGENTS、使用和验收说明，可复用同一文件。
5. 后续按语义影响补约束、检查和知识，标记未验证假设。

不预建完整文档树、Skill 集合、多 Agent 框架或无用途包装脚本。只交付需求/设计时，不声称工程可运行。

## 已有项目：基线与最小补齐

1. 确认是局部补齐还是已授权体系改造；保留用户改动和团队约定。
2. 定位规则、契约、知识和真实路径；复用能承担职责的现有文件。
3. 核对检查入口、依赖、测试清单和版本结果，区分既有失败、环境问题、未运行项和新问题。
4. 说明保留、补齐、去重位置和关键未知；已有授权足够时继续。
5. 增量修改并按项目门槛验证，更新实际受影响的文档和同一任务记录；范围外治理列后续。

不为套模板搬目录、重写架构或复制共享指南，不把历史偶然行为直接升为契约，也不在兼容影响未明时删除。仓外文档、部署边界和保密约定继续有效。

## 项目级 AGENTS 的职责

项目 AGENTS 保持简短，只写：

- 契约、架构、验收和内部资料的权威入口；
- 必须遵守的业务真值、所有权、状态、兼容边界及定义位置；
- 改动对应的配置、命令、验收入口；
- 有依据的更严格要求和项目操作边界。

不复制共享的委派、模型、风险、审查和完成规则；写清它们在项目中的具体落点。详细文档不强制命名；不同 CLI 按真实加载机制转发同一规则。

执行者必须能访问规则。个人路径不复制进团队仓库；跨机器/CLI 传递按[协作指南](agent_selection.md#最小任务说明与结果)。不可达时说明，不能假称已加载或继承上下文。

## 文档与持续上下文

每类事实只有一个权威维护位置，其他文件引用。契约、架构、重要决定、持续任务状态和运行证据可分别位于项目允许的仓库或内部系统；原始证据需有可定位、关联版本的索引。

记录更新与恢复见[上下文管理](engineering.md#context-management-and-resumption)。Git 历史不能替代未完成调查的假设、失败实验和下一步；短任务不强制建记录，长任务不维护重复记录。

内部资料用允许的标识、版本或索引定位。凭据、敏感现场数据和个人路径不得进入公开/团队仓库。未知内部位置只记录线索和缺口，不虚构链接或声称已更新；仅在阻塞必要工作时询问。

## 测试与验收体系

项目把[证据规则](engineering.md#evidence-and-confidence)和[独立审查规则](engineering.md#independent-review-policy)映射为受影响范围、真实检查入口、必要环境、场景/预期和结果位置；已有文档或 CI 足够时不另建表。

核对依赖、注册、路径和命令，并实际执行当前目标所需检查。文件存在、测试已注册或历史绿灯都不能证明最终版本通过。

真实集成按需覆盖准备数据、启动就绪、关键路径、外部状态/日志观察、清理和再次运行。区分本机、目标平台和真实集成；环境不可用时保留验收项并报告影响。CI 可在仓外，必须定位其入口和对应版本结果。

证据按[最小任务说明与结果](agent_selection.md#最小任务说明与结果)交付，不另搭复杂日志系统。

## 可选 Skill 能力导航

只按宿主暴露的名称和描述识别候选；安装、可调用、显式启用和验证是不同状态。按 [Skill 使用](../AGENTS.md#skill-使用)，仅用户明确请求后读取或使用；创建/安装不授权启用配套 Skill、提交或发布。入口未确认时不猜命令，个人路径和适配记录留在本机。

## 重复动作的沉淀与告知

### 触发判断

以实际重复或同类失败复现触发，不按固定次数创建 Skill。原则写文档，确定性动作放脚本/CI；只有稳定、可复用且需要判断的多步骤过程才列为 Skill 候选。

### 复用与落位

优先扩展现有入口，不建平行版本或外观包装。未经用户请求不读、调用或遵循 SKILL.md。通用治理、项目资产和跨项目个人资产按既有边界放置。Skill 引用权威规则，机械动作交脚本，不复制整套文档或写死项目路径。

### 交付告知

有实质收益时交付“建议/暂不建议”、理由、范围和位置；候选不授权自动创建/安装。用户明确要求沉淀后一次完成，无需重复确认。

创建或更新后主动给出名称、路径、场景、显式调用示例、实际验证和限制。创建不等于启用；以宿主发现为准。至少验证一个代表场景和一个不适用边界，未运行不得声称验证；流程变化时更新或停用旧入口。

## 持续维护与接入完成

按影响更新权威位置：行为/兼容改契约，结构改架构或决定，构建/配置/测试/环境改对应入口，持续工作改同一记录。小型无语义改动不要求新 Spec、ADR 或任务文档；重复失败和失效入口按 [工作流改进](workflow_evolution.md)处理。

接入完成要求本次范围内的依据/职责可定位、规则可达、运行与验证前提及结果已核实、持续记录可找、缺口和下一步明确。阻塞当前目标的缺口未解时不能称完成。

规则文件存在不等于项目能运行；接入完成不等于产品验收通过或已发布。交付按[完成条件](engineering.md#persistent-records-and-completion)说明实际范围和证据限制。
